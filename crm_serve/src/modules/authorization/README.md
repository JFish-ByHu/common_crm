# 运行时授权

`PermissionGuard` 是全局守卫，先校验 access token、有效会话和账号状态，再匹配数据库里的接口规则。
普通用户请求未绑定规则的业务接口时默认返回 HTTP 403，不因前端隐藏按钮而省略服务端校验。
系统管理角色拥有全部业务接口权限，包括新注册但尚未配置的接口。

公共接口固定为根健康响应、`health`、`auth/login`、`auth/refresh`、`auth/logout`。
`auth/me`、`auth/heartbeat`、`auth/password`、`authorization/current` 需要登录，不需要业务授权。
这些是认证基础设施语义，不能在菜单配置中改成公共接口或另行绑定业务权限。
其他新增 Controller 接口自动进入权限约束范围，无需额外添加权限装饰器。
接口清单从 Controller 路由元数据发现；守卫使用 Express 匹配到的模板，排除 query 参数和用户输入路径对匹配的影响。

## 接口清单同步

每次后端启动（包括 watch 编译后重启）在全部模块初始化完成、开始监听请求之前，对比接口清单与数据库绑定。
删除或改名的路由、已移出业务授权范围的接口，会自动删除旧绑定；按钮及角色授权记录保留。
改名后的新路径会出现在接口选项中，需管理员重新绑定，普通用户在绑定前默认无权调用。
清理在事务中锁定权限版本行，删除绑定、递增版本、记录包含旧规则的审计一起提交；没有失效规则时不修改版本、不写审计。
发现空接口清单时中止启动，避免扫描异常导致全量误删；清理失败也不会继续启动。
多实例必须使用同一套路由版本再执行启动同步，不支持新旧路由版本同时写入同一权限库的滚动部署。

## 缓存一致性

Redis key：`<环境前缀>:authz:<数据库权限版本>:<userId>`，TTL 120 秒。
每次业务鉴权读取数据库版本后查缓存；角色授权、角色启停/编辑/删除、用户角色分配及菜单按钮修改都在提交事务中递增版本。
版本变化后旧缓存不再被读取，自然过期；Redis 故障时直接从 MySQL 计算，数据库故障返回 503，不放行。
已通过鉴权的进行中请求不会被追溯撤销；后续请求使用提交后的版本。

## 前端路由

Alpha 展示授权菜单树并控制顶层导航；各子应用根据授权页面动态注册自己持有的组件。
只允许加载子应用组件注册表里的能力，后端字符串不会用于任意动态 import。
页面只隐藏导航时仍可以直接访问；无授权路径显示无权限页面。
控制台、登录及无权限页面是固定基础页面。
Alpha 统一加载当前会话的权限，使用 60 秒内存缓存并合并并发请求；子应用通过共享能力读取同一份结果，动态路由重新匹配不会重复请求接口。子应用独立运行时使用相同的本地缓存策略。
当前浏览器保存配置或分配角色后强制刷新一次，直接更新基座和操作所在子应用，不再通过事件额外请求。强制刷新会等待变更前的在途请求结束，再读取提交后的权限。
其他已打开浏览器的菜单和按钮在缓存到期后的路由切换或页面刷新时更新；后端权限仍在变更提交后即对新业务请求生效，不受前端缓存影响。
缓存不落盘，会话 token 改变时重新加载；加载失败清空结果，不保留旧权限作为降级放行依据。
界面通过 `hasPermission('system:users:create')` 等完整权限标识判断按钮显示或禁用；后端守卫不信任前端提供的权限集合。
