# 数据库查询恢复

`PrismaService` 作为全局单例管理连接池，启动时连接、销毁时断开。
锁屏本身不会关闭数据库连接，但自动睡眠、网卡节能、网络设备或 MySQL 回收空闲连接，
都可能导致隔夜后的第一次查询遇到失效连接。是否发生睡眠或网络中断需结合系统和数据库日志确认。

## 有限只读重试

`readWithRetry(() => 新查询)` 用于可重复执行的只读查询：

- `P1001`（无法连接）、`P1002`（连接超时）、`P1017`（连接关闭）时等待 300ms，再执行一次。
- 首次查询失败但第二次成功时，按正常业务结果返回，不进入 HTTP 异常日志。
- 第二次仍失败时原样抛出，由统一异常过滤器返回 503 并记录限频日志。
- 连接池等待超时、连接数超限、慢查询超时、参数和业务错误不自动重试。

已接入账号查询、会话校验、在线状态所需的数据库查询、用户列表及下拉列表。
列表统计的只读事务会整体重建，列表与总数继续使用同一事务快照。
回调必须创建新的查询，不能复用已执行的 PrismaPromise 或已失败的事务客户端。

新增、编辑、删除、会话创建和 token 轮换等写操作不进入该重试逻辑。
断线时写操作是否已提交可能不确定，直接重放会带来重复写入风险。

连接的回收和重建由 Prisma 管理，不在请求期间调用 `$disconnect()`，
避免重置共享连接池、中断其他请求或事务。不通过定时 `SELECT 1` 保活，
单次探测无法保证池内每条连接有效，也无法防止机器睡眠或真实断网。

此处理可以吸收部分短暂故障，不能保证持续断网期间请求成功。
总等待时间包含两次数据库连接/查询耗时及 300ms 间隔，仍受客户端请求超时限制。
客户端若先超时不会取消已发出的数据库查询。
持续故障需要排查网络、MySQL 服务及其错误日志，不能通过吞掉错误解决。
