# 服务端异常响应

`HttpExceptionFilter` 通过 `APP_FILTER` 全局注册，负责 HTTP 请求执行期间未处理的异常，
包括守卫、Controller、Service 中向外抛出的数据库错误。

Prisma 连接失败、连接超时、操作超时、连接断开、连接池等待超时和连接数超限
（`P1001`、`P1002`、`P1008`、`P1017`、`P2024`、`P2037`）返回 HTTP 503：

```json
{
  "code": 503,
  "data": null,
  "msg": "数据库暂时不可用，请稍后重试"
}
```

其他未处理异常，包括未被业务层处理的 Prisma 错误，返回 HTTP 500：

```json
{
  "code": 500,
  "data": null,
  "msg": "服务器内部错误，请稍后重试"
}
```

原始异常仍记录在后端日志中，不向客户端暴露数据库地址、SQL 或调用堆栈。
业务 Presenter 已处理的错误继续使用原有响应；`HttpException`（如鉴权 401、参数校验 422）
交给 Nest 原有处理，不改变其 HTTP 状态码或响应内容。

该处理只统一错误响应，不修改连接池、不自动重试、不将数据库异常视为登录失效。
数据库故障响应不带开发代理的重试标记，因此不会触发客户端的开发服务重启重试。
应用启动阶段的连接失败不属于 HTTP 请求异常，仍按原有启动错误处理。
