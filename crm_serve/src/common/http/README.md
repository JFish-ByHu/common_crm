# 服务端异常响应

`HttpExceptionFilter` 通过 `APP_FILTER` 全局注册，负责 HTTP 请求执行期间未处理的异常，
包括守卫、Controller、Service 中向外抛出的数据库错误。

Prisma 连接失败、连接超时、操作超时、连接断开、连接池等待超时和连接数超限
（`P1001`、`P1002`、`P1008`、`P1017`、`P2024`、`P2037`）返回 HTTP 503：

```json
{
  "code": 503,
  "data": null,
  "msg": "数据库暂时不可用，请稍后重试"
}
```

其他未处理异常，包括未被业务层处理的 Prisma 错误，返回 HTTP 500：

```json
{
  "code": 500,
  "data": null,
  "msg": "服务器内部错误，请稍后重试"
}
```

上述数据库可用性错误只记录错误码、中文原因和排查方向，不重复打印 Prisma 调用堆栈。
每个进程内，同一错误码首次立即记录，随后 60 秒内的同类日志合并计数；
窗口结束后的下一次同类错误会输出摘要和已合并数量。没有新错误时不额外输出日志。
这只限制日志数量，每次失败请求仍返回 HTTP 503。其他未知异常继续记录原始异常，
不向客户端暴露数据库地址、SQL 或调用堆栈。
业务 Presenter 已处理的错误继续使用原有响应；`HttpException`（如鉴权 401、参数校验 422）
交给 Nest 原有处理，不改变其 HTTP 状态码或响应内容。

异常过滤器只统一错误响应和日志，不修改连接池、不自动重试、不将数据库异常视为登录失效。
部分只读查询在到达过滤器前会做一次连接故障重试，详见 [数据库查询恢复](../../database/mysql/README.md)。
数据库故障响应不带开发代理的重试标记，因此不会触发客户端的开发服务重启重试。
应用启动阶段的连接失败不属于 HTTP 请求异常，仍按原有启动错误处理。

## 反复出现 P1001 时

`P1001` 表示后端无法连接 MySQL，报错中的 repository 行号只是触发查询的位置。
基座心跳约每 60 秒请求一次，用户列表在线状态约每 30 秒轮询一次，这些请求的守卫
都要查询数据库验证会话。数据库连接异常期间，即使没有手动操作页面也会产生失败请求。

请在故障发生时检查后端机器到数据库端口的连通性，以及 MySQL 服务、云安全组、
防火墙和网络连接。端口连通只证明 TCP 连接成功，仍需用只读查询确认数据库可用。
偶发错误应结合故障时刻的 MySQL 错误日志、重启记录和连接指标排查；
`P2024` 还需检查慢查询及锁等待，不应直接通过增大连接池掩盖问题。

数据库恢复后后续请求会重新尝试正常查询；不会缓存鉴权成功结果来绕过会话校验，
因此强制登出和停用账号仍按原有逻辑生效。
